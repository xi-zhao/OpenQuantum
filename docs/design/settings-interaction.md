# 设置页交互原型

日期：2026-10-29。目标：电脑端的 OpenQuantum 设置窗口与 Codex 应用。交互稿：[打开原型](settings-prototype.html)。共享正式页面已采用确认后的交互；原型保留为离线演示。实现约定见 [共享设置页设计](../../runtime/chatgpt/ui/DESIGN.md)。

## 方向

保留 OpenQuantum 标志、系统字体、白色画布、深蓝操作色，以及「首页 / Skills / MCP」导航。Desktop 设置与 Codex 应用均以电脑全屏工作区为主场景，铺满可用宽高，采用可搜索列表与右侧详情。两端不按宿主限制宽度；仅当实际容器窄于 720px 时切换为列表与详情单栏，返回后保留筛选和位置。

首页介绍 OpenQuantum 理念，采用根目录 [README 首屏](../../README.md) 的「共建可信的量子科研智能」标题和第一段平台介绍，说明开放共建及专业软件与研究成果的连接。两端的正文均限制行宽以便阅读，随实际容器宽度自然换行；Skills、MCP 目录入口放在介绍之后。原型默认打开首页，不放固定服务示例、不虚构最近使用或待办。账户配置从对应 MCP 或 Skill 的详情进入。

MCP 列表直接说明账户要求，并将需要处理的字段作为入口。详情首先显示账户表单，其次是运行环境与工具说明。允许使用的开关独立于账户和环境状态。切换服务不会把未保存的输入写入设置，也不会丢弃本页草稿。

原型的关键动作是从「云端待填 Token」直接到对应字段。IBM Runtime、Transpiler 和硬件连接使用当前宿主的同一份 IBM Token；FieldQKit 先选平台；QCArchive 区分公开服务器与用户名/密码配对；Pasqal 云端账户属于 Skill，不伪装成一个 MCP。自建 MCP 的 Token 在独立凭据窗口填写，列表与详情均提供明确入口。

## 状态和安全边界

- 许可、环境、凭据三个状态分别表达，不用一个「已连接」概括。
- 逐字段保存；空输入不能保存，已有秘密不回显，删除需要确认。
- 保存成功只表示凭据已保存，不表示平台认证已验证；不自动发出量子任务。
- Codex 与 Desktop 的账户、环境、许可状态按宿主隔离；共享字段仅在同一个宿主内复用。
- 原型使用本页内存和演示值，不接真实凭据库、不安装环境、不连接云端；刷新可重置。正式实施继续复用现有 Application Interface、加密提交和回读核对，不新增秘密存储。
- 原型中的目录是真实源码快照；许可、环境和已保存标记是明确标注的演示状态。

## 目录与分支核验

正式实施以 `main` 的 `ea2b8c1d` 为基线，在 `c/settings-main` 整合本次原型和共享页面；没有带入旧任务分支中的独有科研提交。源码及重建目录均含 186 个 Skills、91 个 MCP 声明，新增的 `lean-physics`、`emlint-dem-audit` 已可搜索。离线原型已同步该目录。

正式页面使用各宿主的实际 snapshot：Codex 隔离预览有 91 个 MCP 项；Desktop 还会并入其后端注册的 Provider，当前隔离宿主显示 92 项。数量差异不能据此解释为共享目录丢失。两个宿主均显示 186 个 Skills，另列两个未关联的内置 Tool，不把 Tool 算作 Skill。

本次未替换用户已安装应用、发布新版本或验证其安装状态。源码和本地预览通过不表示已安装应用已经更新。

## 验收范围

浏览器检查应覆盖：两种电脑容器、搜索与筛选、列表和详情返回、演示凭据的保存/替换/移除、IBM 共用字段、宿主隔离、FieldQKit 平台切换、QCArchive 字段配对、Pasqal 认证方式、无凭据服务、自建 MCP 凭据窗口，以及键盘焦点和无横向溢出。这里只验证原型交互，不替代正式应用的集成与安全测试。

实际浏览器验证：15 组交互检查通过（包含自建免认证连接与统一筛选的回归），无 JavaScript 错误，无外部请求。两种容器在 360–1440px 视口下均无横向溢出；正文、辅助文字与账户提示对比度分别为 15.69、5.68、5.81。检查使用演示值，未读取或改写真实账户。

随后按用户澄清，将两端统一为全屏工作区，并删除首页副标题和第二段介绍。原型在 1440×1000 视口中使用 1392px 的工作区宽度（外侧各留 24px 展示边距），MCP 列表和详情并排；800px 与 460px 视口无横向溢出。

正式页面另行验证：Codex 隔离 Application 预览通过 8 组浏览器流程，覆盖首页、最新目录、搜索、IBM 草稿与加密保存/移除、FieldQKit 平台、QCArchive 配对、Pasqal 认证、自建连接及响应式返回；另有 4 组检查验证初始读取失败恢复、键盘导航、中文输入法和窄窗返回时的位置/焦点保留。Desktop 在真实 Harness Web Host 的设置 Modal 中核验，1440×1000 窗口内共享 iframe 为 1342×768，目录/详情为 304px/990px；没有横向溢出和页面错误。未调用模型、安装计算环境或连接量子云。这里的 Codex 验证使用 HTTP 预览分支，未替代实际 Codex MCP Apps 宿主验收。

插件测试 139 项：131 通过，8 项按条件跳过，0 失败。宿主、凭据迁移和恢复测试 33 项：31 通过，2 项按条件跳过，0 失败；最终宿主样式修改后的相关回归再次通过。ESLint、差异检查和 Impeccable 设计检查通过。
