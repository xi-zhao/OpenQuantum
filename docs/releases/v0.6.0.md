# OpenQuantum v0.6.0 — 量子软件生态扩展 / Quantum SDK expansion

v0.6.0 把近期加入的国内外量子 SDK、算法示例和互操作工具汇集到同一发行版。用户可以从问题出发，让 Agent 选择已支持的方法，调用本地计算或已配置的服务，并查看实际输入、输出和适用的验证记录。

## 本版可以多做什么

| 任务 | 新增或扩展的入口 | 返回什么 |
| --- | --- | --- |
| 可微分电路与变分方法 | PennyLane、DeepQuantum、TensorCircuit、MindQuantum、VQNet；Qcover 参数评估 | 概率、Pauli 期望、梯度或给定参数的能量 |
| 电路编译、仿真与混合程序 | TKET、QSteed、MQT QMAP / DDSIM、QCompute、Qibo、Braket LocalSimulator、Guppy / Selene 等 | 门集与线路映射、态矢或采样，以及测量、复位和经典反馈结果 |
| 容错资源与量子化学 | Microsoft QDK、Qualtran、QURI Parts、OpenFermion、pyChemiQ；可选 QCArchive 查询 | 带假设的资源估算、期望值、Pauli 算符和既有分子计算记录 |
| 原子与光子计算 | QuEra Bloqade Analog、Pulser、Perceval、Lightworks、MerLin；可选 MrMustard | 原子占据与末态概率、光子 Fock 概率、相移梯度或光学矩 |
| 实验控制准备 | Quantum Machines QUA、Zurich Instruments LabOne Q、Qblox Scheduler、Qililab、OQC QAT | 程序、排程、离线编译结果与波形；当前适配不执行实验室设备程序 |
| 网络与服务接口 | SimQN、NetQASM，以及按需启用的 AQT、OQC、Quantum Inspire、Classiq、Q-CTRL、Superstaq 等 | 链路统计、程序、设备或任务查询；部分接口提供需单独授权的远程动作 |

三批 SDK 接入共新增 **52 个能力包、52 个 Skill、52 个 MCP 连接和 60 个 Tool**，详见 [17 项厂商 SDK](../integrations/VENDOR_SDKS.md)、[20 项公司与机构能力](../integrations/SDK_EXPANSION.md)及 [15 项网络、控制、光学与云接口](../integrations/SDK_GAPS.md)。[Bloqade Analog](../integrations/BLOQADE_ANALOG.md)另有独立适配。这里的接入只涵盖文档列出的动作，不表示开放上游 SDK 的全部 API。

本版也包含 v0.5.1 之后的其他主线成果：

- **算法学习与复算**：66 份 quantum-skills 指南适配为原生 Skill，其中 49 项提供可执行示例，覆盖上游 39 个算法模块及指南独有方法；使用开放后端，保留替换差异与来源。见[覆盖表](../integrations/UNITARYLAB_OPEN_COVERAGE.md)。
- **互操作与计算工具**：qBraid 的 Qiskit / Cirq 转换、Clifft 中间测量与原始奇偶记录、QDMI 只读驱动发现，以及 QCut、Compact、OpenQARP、cqlib-qml 与 FlagQuantum 的对应适配。见[互操作](../integrations/QUANTUM_INTEROP.md)和[计算能力](../integrations/CANDIDATE_LIBRARIES.md)。
- **环境与使用说明**：计算环境显式准备，缺少依赖时返回准备指引；README 十种语言同步本版能力、配置与升级范围。修复资料检索集成测试中辅助模型请求提前消耗测试用例的时序问题。

本版本的静态目录为 **154 个 Skill、90 个 MCP 连接、281 个可配置 Tool 名称**。这些是发行版配置数量；实际会话可用集合取决于平台、准备环境、连接开关和工具范围。Skill、Tool 和 MCP 连接分别统计。

## 下载与升级

从 [v0.6.0 Release](https://github.com/xi-zhao/OpenQuantum/releases/tag/v0.6.0) 下载实际发布的附件。安装包为**未签名测试构建**，尚未完成 Apple 签名、公证或 Windows 签名。

| 平台 | 安装文件 |
| --- | --- |
| Mac，Apple Silicon | `OpenQuantum-0.6.0-macOS-arm64.dmg` |
| Mac，Intel | `OpenQuantum-0.6.0-macOS-x64.dmg` |
| Windows，64 位 | `OpenQuantum-0.6.0-Windows-x64-Setup.exe` |

Release 附带的 `SHA256SUMS` 用于核对三个安装文件。安装包内置工作台、Node.js 和 uv；量子 SDK 的计算环境、Julia 和量子学习通等可选组件仍按各自说明准备。

已有安装版请先结束任务、退出应用并备份[用户数据目录](../DESKTOP_INSTALLERS.md#数据与升级)，再覆盖安装。会话、凭据和用户改动会保留；用户改过的内置 Skill 或 MCP 配置不会被新版静默覆盖。对应新默认文件保存在 `project/.openquantum/distribution-defaults/`，需要比较后采用。新增文件会随发行版准备，但保留的旧 Preset 可能仍需采用新增连接配置。

源码用户在保留已有改动后使用干净的 `v0.6.0` checkout，运行 `npm ci`；Desktop 源码用户还需运行 `npm run desktop:setup` 和 `npm run desktop:verify-install`。所选能力按[环境准备说明](../integrations/LOCAL_ENVIRONMENTS.md)安装，例如：

```sh
node scripts/setup-paper-tools.mjs bloqade-analog qdk-resource-estimation
```

批量入口分别为 `capability:vendor-sdks:setup`（17 个环境）、`capability:sdk-expansion:setup`（14 个默认环境）和 `capability:sdk-gaps:setup`（7 个默认环境）；可选能力仍按 ID 单独准备和启用。不同 SDK 的 Python 版本、系统支持与许可条件保留在各接入说明中。

模型服务与量子云账户、密钥、权限由用户自行配置。安装依赖、启用连接和允许具体云任务是独立操作。设置中的版本更新只提供提醒与发布页入口，不自动下载安装或重启。见[完整升级说明](../UPDATES.md#upgrading)。

## 验证范围与兼容性

本版保留 Harness `0.1.5-rc.1`、Desktop `2.0.7`，以及锁定的 Node.js `24.14.1`、uv / uvx `0.11.1` 安装运行环境。

新增 SDK 的既有接入证据来自 **macOS arm64 的固定 SDK、本地数值对照、MCP 合同和 Harness 本地模型协议夹具**。远程接口主要用真实 SDK 配合受控 HTTP / 传输响应验证。证据分别见[厂商批次](../integrations/evidence/vendor-sdks-2026-09-27.json)、[公司与机构批次](../integrations/evidence/sdk-expansion-2026-09-28.json)和[补充批次](../integrations/evidence/sdk-gaps-2026-09-28.json)。这些历史接入检查与本次发行检查分别记录。

- 三平台安装检查覆盖安装文件、工作台启动、内置运行环境、用户数据保留和固定本地 Tool，不代表每个新增 SDK 已在全部平台运行，也不覆盖所有首次设置向导的人工交互。
- 未新增真实云账户、付费作业、QPU、实验室设备或外部模型的验收结论；新增 SDK 能力保持 L1 / `scientificValidation=not_evaluated`。
- NetQASM 程序编译已有验证；SquidASM / NetSquid 数值仿真仍需用户另行准备有许可的依赖。CUDA-Q、MIMIQ Exaqt 等有平台限制；MrMustard 使用已归档的固定版本；Qblox Scheduler 使用固定预发布版本。
- 运行成功、接口适配和科学验收分别判断。沿用已有科学验收能力，不将全部新增接口表述为已通过科学验收。

正式附件须通过同一提交的源码 CI 和三平台原生安装检查，并核对上传后的大小与摘要；实际结果以 [CI](https://github.com/xi-zhao/OpenQuantum/actions/workflows/ci.yml)、[安装包检查](https://github.com/xi-zhao/OpenQuantum/actions/workflows/desktop-installers.yml)和版本附件为准。稳定更新清单由发布工作流在质量门通过后附加。

## English

OpenQuantum v0.6.0 brings recent quantum SDK integrations, algorithm examples and interoperability tools into one distribution. Three integration batches add **52 capability packages and 60 Tools**, alongside the separate QuEra Bloqade Analog adapter. The task coverage includes differentiable circuits, compilation and local simulation, fault-tolerant resource estimates, chemistry operators and records, atom arrays, photonics, offline pulse compilation and quantum networks.

The release also includes the 66 adapted quantum-skills guides, 49 executable workflows, qBraid / Clifft / QDMI interoperability, and the QCut, Compact, OpenQARP, cqlib-qml and FlagQuantum integrations added after v0.5.1. Each adapter exposes its documented actions; upstream APIs are not claimed to be fully supported.

The static inventory contains **154 Skills, 90 MCP connections and 281 configurable Tool names**. These are catalog counts, not a guarantee that every Tool is available in every session. Dependencies, connection activation, platform requirements and licenses apply separately. Users configure their own model services and quantum-service accounts, credentials and permissions.

Downloads are attached to the linked GitHub Release for Apple Silicon Macs, Intel Macs and Windows x64, with `SHA256SUMS`. The installers are **unsigned test builds**. They include adapter code, Node.js and uv; prepare the computing environments you choose. Back up data and quit the application before upgrading. Modified Skills and MCP settings are retained, with new defaults stored for comparison. Existing source installations are not migrated automatically. The update service provides reminders, not unattended installation.

The pinned Harness and Desktop versions remain `0.1.5-rc.1` and `2.0.7`. Recorded SDK integration tests were performed on macOS arm64, using real local SDKs, numerical references and local model or transport fixtures. Installer validation does not certify every optional SDK on every platform. No new live-account, paid-cloud, QPU, laboratory-hardware, external-model or scientific-acceptance result is claimed. New adapters retain L1 / `scientificValidation=not_evaluated`; licensed NetSquid simulation and documented platform limits remain applicable.
