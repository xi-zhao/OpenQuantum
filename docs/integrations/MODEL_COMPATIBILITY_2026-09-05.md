# 模型兼容性验收摘要（2026-09-05）

这是一轮通过使用者提供的网关运行的有界兼容性检查，用来回答“模型能否经 OpenQuantum 完成真实工具执行”，
不是官方模型身份认证、能力排名、长期稳定性评测或全部集成服务的上线验收。

本摘要只发布脱敏结论。网关地址、密钥、账户信息、完整 Prompt、原始会话与本机路径不进入仓库。
原始诊断报告和 Session 执行事实仅在本地保留；因此下面是实测摘要，不是完整公开复现实验包。

## 测试边界

- 版本：OpenQuantum `0.4.0`，DeepSeek Harness `0.1.0-rc.6`；使用实际 pi-ai Model Adapter。
- 基础协议：1 次目录请求与 26 次模型请求；无自动请求重试，单次输出上限 1,024 tokens。
- Harness：独立 Home、Session 与工作区；使用项目原生量子 Tool Provider、Scientific Host Plugin 和 Skill Provider，
  禁用通用执行工具与 MCP 连接。验证的是原生量子参考流程，不是所有 MCP Server 的兼容性。
- 每个有权限模型运行一个固定案例；并发 2，每个会话最多 3 个模型请求步骤，每次最多 1,536 输出 tokens。
  共观测到 21 个模型请求步骤。模型因输入错误再次调用 Tool 与 HTTP 自动重试是不同事件，前者按实际记录保留。
- 科学输入使用仓库固定的[二量子位 Pauli Hamiltonian](../../.agents/skills/quantum-ground-state/evals/fixtures/requests/protocol-fixture.json)。
  将模型调用参数与实际提交输入逐项比较，配对 Session `tool/call` 与 `tool/result`，重读 Result Package 与
  Acceptance Report，复核摘要和事件来源链，由 central Acceptance Builder 的结论支持科学验收。
- 测试驱动进程中途退出后，通过现存 Harness Session 恢复检查，未重新运行已完成案例；当时尚未启动的
  `glm-5.1` 补做其首次案例。未把测试驱动问题归因于模型。
- 没有验证长上下文、视觉、长任务、多次重复稳定性、全部 Skill 或真实量子硬件。未核验计费金额。

## 怎样使用这份证据

对四个严格通过的标识，可以在自己的服务和凭据下继续验证接入；对输出格式问题、权限问题和预算截断，
分别处理，不把它们混成“模型不支持”。尤其不能通过放松科学输入校验来把未通过的案例变成通过。

换网关、模型版本、协议配置或输出预算后，应重新验证。仓库现有
[`probe-quantum-harness-e2e.mjs`](../../scripts/probe-quantum-harness-e2e.mjs)提供真实 Harness 科学结果重读的参考检查；
它默认检查固定 Provider Route，不是本次十模型测试的完整复现入口。

此次没有修改正式模型配置或启用云端量子任务。本文记录 2026-09-05（北京时间）的结果，不是持续在线状态。
