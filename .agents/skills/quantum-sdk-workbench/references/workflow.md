# 完整原生 SDK 工作流

## 选择执行路径

便捷 Tool 适合其 schema 能准确表达的任务。用户需要其他模型、态、信道、门、测量、优化器、控制流程、数据或后端时，直接使用 SDK 公开 API。不要为了适配 Tool 而删减用户问题，也不要逐个函数再封装成 MCP Tool。

完整接入指对已固定发行版的公开 API 保持可达、可组合、可编程；不等于所有 API、可选 extras、平台、远程服务和科学结果均已验证。目录中的模块是导航入口，不是调用白名单。库的实际 API 以该版本为准。

## 环境与 API

- 源码/桌面版：从发行版根目录运行 `node scripts/sdk-access.mjs inspect <sdk-id>`。
- Codex 插件：运行本 Skill 目录下 `scripts/sdk-access.mjs inspect <sdk-id>`。它读取插件自己的 MCP 配置以定位外置 runtime，适用于解压包和安装后的插件缓存；不要假设 runtime 位于当前研究项目或插件的 `server/`。
- `list` 给出项目、库名、模块、任务对象与条件；`inventory` 给出依赖和锁定版本。命令返回 argv 数组，调用宿主工具时保留每个参数，路径含空格时正确引用；不要把 JSON 序列化当作 Shell 转义。
- `inspect` 的 `setup` 是显式依赖准备，`run` 是解释器调用模板。确认 `environmentState=prepared` 后用用户脚本绝对路径替换占位符。Julia 还需核实固定版本与 `Pkg` 环境；QDMI 需检查构建输出和 ABI，其他原生入口返回构建后的可执行文件。
- 可用 `OPENQUANTUM_JULIA` 指定解释器，`OPENQUANTUM_JULIA_DEPOT_PATH` 指定 Julia depot；定位器返回的 `run.environment` 与命令一起传给宿主工具。源码及原生构建缓存可用 `OPENQUANTUM_SDK_SOURCE_ROOT` 和 `OPENQUANTUM_NATIVE_SDK_ROOT` 外置。
- 大型依赖下载受网络和缓存磁盘影响。显式 Python setup 可继承 `UV_CACHE_DIR`、`UV_CONCURRENT_DOWNLOADS`、`UV_HTTP_TIMEOUT`、`UV_HTTP_RETRIES` 与 `UV_LINK_MODE`；这些设置只影响准备过程，不改变依赖锁。失败后仍需成功完成 setup 才能标记 prepared。
- 通用 Python setup 与算法环境 setup 在标记成功前检查 wheel 的原始 `RECORD` 所列文件是否存在、大小是否完整。磁盘写满后，即使 uv 的元数据检查成功，残缺文件仍会阻止标记；按同一锁与环境重装报告的依赖，再重新 setup。该检查不导入 SDK，也不证明 API 或数值行为正确。
- 文档先查已安装模块的 docstring、`help()`、`inspect.signature()` 和包元数据中的官方文档。只读取相关模块，不递归导入全部子模块；导入也可能产生缓存或尝试连接外部服务。发现 API 与示例版本不符时修正任务代码，不能伪造兼容接口。
- 如果 `inspect` 返回非空 `bootstrap`，Agent 在保存的任务脚本开头通过 `importlib.util.spec_from_file_location` 加载其绝对 `path`，然后调用 `prepare_sdk(<sdk-id>)`，再导入该库。该入口处理锁定版本的导入兼容、完整源码路径、离线数据和遥测设置；它不执行研究程序。VQNet 和 QPanda 的 macOS loader 可能重启当前脚本一次，必须将 bootstrap 放在任何任务写入之前；不要从 stdin 或 `-c` 执行这些路径。Flow-VQE 使用显式 setup 准备的完整固定源码。PairInteraction 默认使用已核验数据库，其他数据快照通过 `data_directory` 指定，计算阶段不下载。
- 需要额外插件、GPU wheel 或另一版本时，在用户项目建立独立锁定环境，并说明与默认环境的差异。不要升级共享环境来满足一个任务，不把可选组件缺失说成库不支持该功能。
- 不同环境通过 SDK 官方序列化格式或显式定义的文件合同交换结果，记录单位、位序、精度和版本。不要为跨库组合把所有 SDK 强装进一个环境。

## 根据研究对象组织代码

| 对象 | Agent 应完成的实现 |
| --- | --- |
| 动力学与多体 | 从用户输入构造 Hilbert 空间、Hamiltonian、初态、耗散与观测量；选 solver、精度、时间网格；开放自定义 lattice、MPS/MPO、控制和收敛配置。 |
| 电路、编译与 QML | 使用原生电路、算符、控制流、pass、设备和梯度对象；允许自定义 ansatz、损失、executor、数据集与优化循环。 |
| 纠错与测量 | 从用户码、校验矩阵、噪声、测量记录或 detector model 构造实验；选择译码器与批处理，保留失败与统计样本。 |
| 化学与资源估计 | 接收用户分子、积分、活性空间、对称性、算符或 Bloq；资源估计保留模型假设，化学求解保留基组与近似。 |
| 光学与网络 | 构造任意受支持输入态、光学网络、信道、拓扑、事件与协议；明确截断和损耗模型。 |
| 云、控制与硬件 | 先构造并检查用户程序和设备配置，再按用户授权连接或提交；保留 job id、队列、费用约束、取消与结果获取路径。 |

## 运行、失败与工件

任务目录由用户工作区拥有。建议保留 `program.py`/`program.jl`、输入文件、运行配置、日志和完整结果文件；文件名可按项目调整。Agent 编写可重复调用的函数或 CLI，参数扫描从输入读取，不能把研究参数固定在示例中。

运行前估计内存、执行时间、并行度与输出规模。MCP 便捷 Tool 的单次预算不限制宿主代码路径的功能；宿主、机器和用户的资源限制仍有效。长任务使用宿主已有进程/Job 接口。不能因输出窗口截断而丢弃完整数组，使用 NPZ/HDF5/库原生格式等工件保存，再给摘要。

运行中保留进度和错误。超时、取消、缺依赖、数值不收敛、服务失败都记录为实际状态；不返回另一小案例的成功结果。需要续算时使用上游 checkpoint/序列化接口，保存版本与输入摘要，恢复前检查一致性。源码与输入在失败后仍应保留。

复现记录至少包含：实际解释器、SDK 版本、依赖锁摘要、执行命令和工作目录、输入/源代码哈希、seed、数值精度、后端、资源配置、退出状态、日志及工件路径。不要记录整个进程环境或凭据。可复用随本工作流提供的 `evidence.py` 保存文件哈希和已安装包版本；它不执行计算，也不决定科学验收。

## 权限与验收

原生 SDK 代码通过宿主的普通执行与文件工具运行。Skill 不执行代码、不持有密钥，不注册通用任意代码 MCP。已有 Tool 的禁用、用户拒绝的动作、账户权限及外部写操作边界仍然有效；换成 Python 不构成新增授权。不要从插件凭据存储自行导出密钥。

工程检查可验证任意输入可表达、公开 API 可调用、输出可保存、失败可诊断、任务可取消与继续；小输入只是接口测试数据，不能变成功能上限。安装成功、模块导入、上游示例通过都不足以证明全部 SDK 工程兼容。科学结论另按 Validator、Acceptance Profile 和 central Acceptance Builder 的证据链判断；本轮补齐不以真实科研任务验收。
