# 原生 SDK 工作台

用户提出计算或程序实现任务时，Agent 负责完成代码、执行、调试和工件交付。不能只让用户自行转到 Python 或 Notebook。

1. 从 `node scripts/sdk-access.mjs list` 选择项目；`inspect <sdk-id>` 返回绝对解释器路径、锁摘要、准备命令、模块导航与已知条件。`inventory` 包括现有 Tool、依赖组与每个固定版本。命令只读，不安装、不导入 SDK、不执行用户程序。
2. 按[原生 SDK 工作流](references/workflow.md)完成任务。先核实所需 API 在已安装版本中的公开文档与签名，再在用户工作区构造模型和算法；便捷 Tool 的示例不是功能白名单。
3. 在宿主已有的文件和代码执行 Tool 中使用返回的解释器，工作目录设为用户项目。资源预算、长任务、取消和恢复由宿主管理；不要新建执行服务或隐藏后台进程。
4. 保存源代码、输入、完整输出、日志、依赖锁摘要和可复现命令。执行状态与科学结论分开；没有 central Acceptance Builder 证据时，`scientificValidation=not_evaluated`。

`prepared` 只说明解释器与环境标记匹配锁，不代表所有模块已验证。可选组件、外部服务、GPU、设备驱动和许可需要逐项核实。不得因为 Tool 未启用、审批被拒绝或凭据缺失而借代码路径绕过用户选择。

默认使用已准备环境。任务需要而环境缺失时，按已有授权运行显式 setup；不要在计算时自动安装依赖。原生代码的副作用由代码实际行为决定，不能继承只读 Tool 的声明。
