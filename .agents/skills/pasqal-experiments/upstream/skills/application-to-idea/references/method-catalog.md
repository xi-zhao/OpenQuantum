# Method catalogue

The candidate methods, each with a maturity level. Cite a method by its ID in the
note; an ID that is not in this file is not a documented method and must be
labelled as such.

## Maturity levels — use these six words and no others

| Level | What it means |
|---|---|
| `ready_library` | a public application library dedicated to this problem class |
| `documented_recipe` | an end-to-end public tutorial or a reproducible documented workflow |
| `documented_primitive` | a documented Pulser capability that still needs adaptation |
| `research_pattern` | scientifically motivated or demonstrated, with no generic supported workflow |
| `planned_or_adjacent` | belongs to a future capability or to another part of the stack |
| `no_fit` | no sufficiently justified Pulser-compatible method |

**Never promote a `research_pattern` to a `ready_library`.** The level is what
tells the user how much of the work has been done by somebody else; inflating it
is how a three-month project gets sold as an afternoon.

## Optimization

### `mwis-qaa` — maximum weighted independent set

**Use when** the user must select valuable items, some pairs are incompatible, a
candidate solution is a subset, and the objective is the sum of selected weights.

**Mapping**: items → vertices → atoms; incompatibilities → edges → blockade;
values → vertex weights → local detuning; solution → a measured independent set.

**Outputs**: best valid sets, total weight, validity rate, probability of the top
candidates, comparison against classical MIS heuristics or an exact solver.

Maturity: `ready_library` — through QUBO Solver, not the standalone MIS library.

### `mis-qaa` — unweighted independent set

The unweighted special case: the largest set of pairwise compatible elements.

Maturity: `ready_library` — through QUBO Solver, not the standalone MIS library.

### `qubo-qaa`

**Use when** decisions are binary, individual decisions carry costs or rewards,
pairs of decisions carry costs or rewards, and constraints can reasonably be
encoded as penalties.

**Procedure**: derive the QUBO → validate the penalties → analyse coefficient
signs and dynamic range → find an embedding → normalise or rescale → build an
adiabatic drive → emulate → sample → **score every bitstring with the original
objective** → repair or post-process where justified.

**Outputs**: candidate solutions, objective distribution, feasibility rate, best
value, approximation ratio where defined, comparison against classical solvers.

Maturity: `ready_library`.

### `qubo-decomposition-hybrid`

**Use when** the QUBO is too large or too dense to run directly: divide into
subproblems, solve them, combine classically, iterate, post-process.

Maturity: `documented_recipe`. Do not imply that decomposition preserves any
quantum benefit — most of the work is classical, and saying so is the honest
framing.

### `analog-drive-optimization`

**Use when** a valid mapping exists but a plain adiabatic schedule performs
poorly: heuristic drives, custom interpolated drives, Bayesian optimization,
derivative-free optimization, a low-dimensional variational parameter search, or
transfer of parameters between similar instances.

Maturity: `documented_primitive`, or `research_pattern` for the transfer and
variational variants.

### `analog-qaoa-like`

**Use only** when a specific protocol or publication motivates alternating
parameterized pulses. Do not recommend QAOA by default — for the standard
documented Pulser QUBO and MWIS routes, QAA is the supported path.

Maturity: `research_pattern`.

## Ising quantum simulation

### `ising-ground-state-preparation`

**Use for** antiferromagnetic states, Rydberg ordered phases, Z₂ or Z₃ order,
low-energy state preparation, frustrated lattices.

**Procedure**: initialize a simple state → build an adiabatic or quasi-adiabatic
ramp → scan the relevant control → measure order and diagonal observables →
assess finite-size and noise effects.

Maturity: `documented_recipe`.

### `ising-phase-diagram-scan`

**Use when** the user wants phases, crossovers or transitions. Scan detuning,
Rabi amplitude, atom spacing, ramp duration, lattice geometry. Analyse excitation
density, sublattice order, connected correlations, the structure factor, domains,
finite-size effects.

Maturity: `documented_primitive`.

### `ising-quench-dynamics`

**Use for** relaxation, oscillations, correlation propagation, domain dynamics,
non-equilibrium evolution: prepare a state, change one or more controls quickly,
repeat over evolution times, reconstruct the time-dependent observable.

Maturity: `research_pattern`.

### `kibble-zurek-ramp`

**Use when** studying defects generated by crossing a transition: vary the ramp
speed, measure defect density or correlation length, fit the scaling, assess
finite-size and noise effects.

Maturity: `research_pattern`.

### `frustrated-lattice-order`

**Use for** triangular or frustrated geometries. Requires an observable that
genuinely separates the expected phases — the usual failure here is an order
parameter with a finite-size floor high enough to swallow the signal.

Maturity: `research_pattern`.

## XY simulation

### `xy-excitation-transport`

**Use for** localized excitation transport, state transfer, spreading over a chain
or graph, exchange dynamics: prepare an excitation, evolve under the XY
interaction, measure site occupations over time, reconstruct the propagation.

**Observables**: occupation by site, transfer probability, mean propagation
distance, participation ratio, correlations.

Maturity: `documented_recipe`.

### `xy-correlation-spreading`

**Use to** study the growth and propagation of correlations.

Maturity: `documented_primitive`.

### `xy-network-dynamics`

**Use when** a graph or network problem corresponds naturally to excitation
exchange. Requires a compatible coupling structure, a well-defined initial
excitation sector, a measurable output, and device support.

Maturity: `research_pattern`.

## State preparation and control

### `target-state-preparation`

**Use when** the goal is to prepare a state or a class of states. Requires a
target state or order, a measurable objective, a parameterized pulse family,
parameter bounds and an evaluation budget. Parameterize → emulate → evaluate →
optimize classically → validate with noise → assess transfer to the QPU.

Maturity: `documented_recipe` for antiferromagnetic preparation,
`documented_primitive` for a new target.

### `bayesian-pulse-optimization`

**Use for** a small number of expensive-to-evaluate parameters: pulse duration,
ramp breakpoints, detuning values, maximum amplitude, interaction time.

Maturity: `documented_recipe` for AFM state preparation.

### `robust-control-under-noise`

Optimize a noise-averaged objective, then check it on an independent noise
configuration — otherwise the optimizer has fitted one realisation.

Maturity: `research_pattern`.

## Graph machine learning

### `quantum-evolution-kernel`

**Use for** graph classification or graph similarity: graph preprocessing →
neutral-atom encoding → quantum evolution → feature or kernel estimation →
classical kernel model → rigorous ML evaluation.

**Mandatory baselines**: classical graph kernels, structural descriptors, a simple
GNN, and a tabular baseline on graph statistics.

**Mandatory methodology**: fixed and stratified splits, multiple seeds,
appropriate metrics, standard errors or confidence intervals, and no unsupported
advantage claim.

Maturity: `ready_library` for the pipeline — the library exists and is public.
The *scientific* claim on any given dataset remains a `research_pattern`: the
pipeline running is not a result.

### `quantum-graph-features`

Use quantum measurements as features inside a classical graph model.

Maturity: `research_pattern`.

### `quantum-positional-encoding`

Use only when backed by a specific reproducible method.

Maturity: `research_pattern`.

## Sampling and generative methods

### `rydberg-distribution-sampling`

**Use to** sample correlated configurations defined by geometry and a sequence:
physical configuration generation, empirical features, probabilistic modelling,
scientifically justified data augmentation.

Maturity: `documented_primitive`.

### `quantum-generative-model`

Requires a target distribution, trainable parameters, a loss, a training
protocol, classical generative baselines and quality metrics.

Maturity: `research_pattern`. **Do not recommend it because the user said
"generate data".**

### `quantum-reservoir-or-dynamical-features`

Analog dynamics as a feature transformation — only where a public, reproducible
protocol exists.

Maturity: `research_pattern`.

## Protocol reproduction

### `custom-paper-protocol`

**Use when** the user supplies a paper, a patent, a Hamiltonian or an experimental
protocol, no standard recipe applies, and the controls look mappable onto Ising
or XY.

**Output**: the probable physical mode, the mapping from model terms to Pulser
controls, the terms that are unsupported or approximated, the observable, the
feasibility risks, the required adaptations, and the handoff to `idea-to-spec`.

Maturity: `research_pattern`. If the source is already a clean protocol, this
skill is not needed — go straight to `idea-to-spec`.

### `no-documented-pulser-fit`

**Return this when** no meaningful binary or graph formulation exists, the
Hamiltonian is not representable, the output is not measurable, size or
connectivity makes the mapping implausible, the request is generic
electronic-structure chemistry, the request is generic ML with no graph or kernel
formulation, a QUBO conversion would be artificial, or only a high-level
marketing analogy connects the problem to Pulser.

Then explain why no fit was found, what reformulation could change that, which
adjacent tool would be worth investigating, and which classical approach should
remain the default.

Maturity: `no_fit`.
